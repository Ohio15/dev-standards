# install.sh refuses to enrol a target in dep-auto-apply while any workflow
# of its has a `uses:` it cannot classify, and the weekly fleet scan
# (scripts/repo-hygiene-scan.py) reports one. A `uses:` passes only as a
# first-party actions/<name> held to the cache rules, a local reusable
# workflow (read in the same pass), or an exact entry below. Matching is
# exact on owner/repo[/path] (case-insensitive): an entry never covers a
# sub-path, so gradle/actions does not admit gradle/actions/setup-gradle.
# A `cache:` key on a listed action is still refused.
#
# Format: one `owner/repo` or `owner/repo/path` per line; `#` starts a
# comment (whole-line or trailing). Any other line makes install.sh refuse
# every enrolment and the scan report every enrolled repo, until fixed.
#
# Adding an entry is a security review: read the action's action.yml inputs
# and its bundled code at the pinned ref, confirm it neither restores nor
# saves an Actions cache by default (no @actions/cache dependency, no
# cache-service call, no default-on cache input), and record why here.
# Actions that cache by default (Swatinem/rust-cache, astral-sh/setup-uv,
# gradle/actions/setup-gradle, ruby/setup-ruby with bundler-cache) must not
# be listed.
