# What still runs on, or arrives from, GitHub

Inventory taken 2026-11-23 (session 1b63ea6b, brief e26f9441). Ron asked to "verify what is still going, or
coming, through Github" and to start moving everything that can run locally onto Ron-owned infrastructure
(NEXUS, paxson).

**Scope.** This covers execution and data only. GitHub as the git remote is out of scope here. The Forgejo
forge-migration program (decision 17889ec5, plan ee05d2d0) owns that question, along with the GitHub App,
ghcr.io and `gh` usage it already plans to replace. Those items are listed below with that program as their
owner, so nothing is planned twice.

**Method.** Every call was a read-only `gh api` GET over the 93 non-archived Ohio15 repos (98 listed, 5 archived):
- workflow YAML, plus the `runner_name` of the jobs in the last 3 runs of each repo;
- the repo variable `CI_RUNNER` and registered runners;
- `dependabot.yml`, open Dependabot PRs, and Dependabot, code-scanning and secret-scanning alerts;
- hooks, Pages, environments and release assets;
- account packages and notifications.

The raw per-repo JSON and the full table are kept outside the repo, in `D:\Scratch\2026-11-23-github-localization\`
(30-day retention). Anything the token could not read is marked UNEXAMINED, never clean.

## Item 1 in detail: `code_deps.prom`

`scripts/code-standards-cron.sh` step 6 runs `scripts/osv-deps-facts.py` over the same mirror the hygiene scan
uses. It runs after the code-standards export and is degradable: it never delays or blocks that export.

- **Scanner.** OSV-Scanner, pinned in `estate/osv-scanner.version` and built by `scripts/install-osv-scanner.sh`
  with `go install`, so it is verified against sum.golang.org with no unverified release asset.
- **Isolation.** The scanner runs with:
  - `--offline --download-offline-databases`: only the OSV database zips are fetched, and no package list leaves NEXUS;
  - `--no-resolve` and `--no-call-analysis=all`: no repo code is built, loaded or run;
  - a working directory outside the repo;
  - a scrubbed environment whose PATH has no Go toolchain.
- **Series.** It writes these series to a separate textfile, because Steward refuses `code_standards.prom` whole
  if it contains any series outside its allow-list:
  - `code_deps_repo_scanned{repo}`
  - `code_deps_packages{repo,ecosystem}`
  - `code_deps_vulns{repo,ecosystem,severity}`
  - `code_deps_last_run_timestamp_seconds`
- **Positive confirmation.** `repo_scanned` is 1 only when the mirror refreshed this run AND the scanner
  completed with output that parses. A clean repo still exports its package counts.
- **Report.** The per-advisory JSON report is written to `/var/lib/estate-code/work/osv/osv-report.json`.

**First run (2026-11-23, pre-merge, scratch output).**
- All 83 rostered repos were examined, in 4 min 20 s.
- 627 distinct advisories across npm, Go, crates.io and PyPI.
- That is far more than Dependabot shows (44), because alerts are disabled on 63 repos and Dependabot never
  covered most of the Cargo workspaces.

**Status.** Nothing reads `code_deps.prom` yet: Steward ingestion is work item 8276fa8d and APM Phase 4 is
brain d04159db. A failed run leaves the previous file in place with its old
`code_deps_last_run_timestamp_seconds`. Staleness therefore needs an alert on that series, and the reader is
where that alert belongs. Until both exist this feed is a report, not a control.
